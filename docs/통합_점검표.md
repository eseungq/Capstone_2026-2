# 통합 점검표

기준: 백엔드 API 계약 v4. 실제 연결 시험 때 결과·날짜·비고를 채운다. 채운 내용은 다음 보고서 "계획 대비 실적"의 근거로 쓴다.

- 결과 표기: 통과 / 실패 / 해당 없음
- 스크립트는 `inspection-backend/backend/` 폴더에서 실행
- 아래 `<AI>`는 `http://<DGX 100.x>:<포트>`, `<BE>`는 `http://<Mac 100.x>:8080`, `$WK`·`$AD`·`$DEV`는 worker01·admin01·device-door의 Access Token

## 앱↔서버

| 번호 | 구간 | 확인 항목 | 방법(명령·화면) | 기대 결과 | 결과 | 날짜 | 비고 |
|---|---|---|---|---|---|---|---|
| A1 | 앱↔서버 | 로그인 | 앱 로그인 (worker01) | 토큰 발급, 목록 화면 이동 | | | |
| A2 | 앱↔서버 | 토큰 재발급 | Access Token 만료 후(30분) 앱 사용 또는 `POST /auth/refresh` | 새 토큰으로 계속 사용, 로그아웃되지 않음 | | | |
| A3 | 앱↔서버 | 모니터링 | 부품별 요약 화면, 5초 폴링 | 새 접수 건이 5초 안팎에 표시 | | | |
| A4 | 앱↔서버 | 확인 필요 목록 | 큐 화면 | REVIEW_PENDING + 재검사 안 한 FAILED, 오래된 순 | | | |
| A5 | 앱↔서버 | 이력 | 이력 화면 필터·페이지 | 부품·상태·기간 필터 동작 | | | |
| A6 | 앱↔서버 | 상세·이미지 | 상세 화면 | 원본·Grad-CAM 표시, 사진·판정 값 일치 | | | |
| A7 | 앱↔서버 | 이미지 만료 후 재조회 | 상세를 10분 넘게 열어 둔 뒤 다시 조회 | 이전 주소는 만료, 재조회한 새 주소로 표시 | | | |
| A8 | 앱↔서버 | confirm 정상 | REVIEW 건 판정 입력 | 200, REVIEW_DONE으로 변경 | | | |
| A9 | 앱↔서버 | confirm 충돌 | 같은 건에 다른 판정 재전송 | 409 `ALREADY_CONFIRMED` 안내 표시 | | | 같은 값 재전송은 200 |
| A10 | 앱↔서버 | retry 정상 | FAILED 건 재검사 | 202, 새 검사 생성, 원래 건 FAILED 유지 | | | |
| A11 | 앱↔서버 | retry 충돌 | 같은 FAILED 건 재검사 다시 | 409 `ALREADY_RETRIED` 안내 표시 | | | |
| A12 | 앱↔서버 | 기기 토큰 등록 | 로그인 직후 `POST /notifications/devices` | 204, `device_token` 행 생성 | | | Expo 푸시 토큰 발급 가능 여부 확인 |
| A13 | 앱↔서버 | 기기 토큰 해제 | 로그아웃 또는 `DELETE /notifications/devices/{token}` | 해제됨, 없는 토큰도 204 | | | 경로 인코딩은 백엔드 보고 참고 |
| A14 | 앱↔서버 | 푸시 수신 | `APP_PUSH_ENABLED=true` 실행 후 REVIEW·FAILED 건 발생 | 앱 종료 상태에서 알림 수신, 탭하면 상세 이동 | | | 가능하면. iOS는 TBD-14 |

| B2 | AI↔서버 | 실제 모델 전환 | README "실제 AI 연결"의 전환 SQL 실행 후 `GET /parts` | activeModelVersion이 실제 모델, policyActive=false | | | 되돌리기 SQL 있음 |

| B4 | AI↔서버 | DEFECT 사진 (png) | `check-ai-connection.sh <AI> <BE> defect.jpg` | COMPLETED · REVIEW(`DEFECT_PREDICTED`), gradcamStatus GENERATED, CAM 저장 | | | |

| B6 | AI↔서버 | NO_ACTIVATION | 0맵이 나오는 사진 접수 | gradcamStatus NO_ACTIVATION, CAM 이미지 없음 | | | AI가 재현 가능한 사진 제공 시 |
