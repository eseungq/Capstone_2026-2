기준: [API 계약 v4](백엔드_API계약_v4.md), [통합 점검표](통합_점검표.md), [backend/README](../backend/README.md) "시연 정책", [mobile/README](../mobile/README.md)

> **11/11 결정: B 구간(자동 통과 정책)은 실제 AI 카울커버(8778, 시연 기준 1.63%)로 진행**합니다. 카울커버는 보정기가 있어 실서버에서 AUTO_PASS가 나오고, 정상 사진 01(약 1.45%)이 검증 범위(1.00~1.63%) 안이라 기준치 조정 효과도 실제 모델로 보여줄 수 있습니다 (김도현 ai/VALIDATION.md).
>
> 도어 e02(8771)는 보정기가 없어 **모든 결과가 작업자 확인(REVIEW)** 입니다(A 구간). 시연 기준(1.63%)은 평가 사진에 사후 적용한 값으로 운영 기준이 아니라는 점을 설명에서 밝힙니다. 앱의 도어 Mock 화면(11/12부터 0.84→0.92%, PR #24)은 실서버 장애 시 **백업**으로만 씁니다.

## 1. 시연 구성

| 구간 | 보여줄 것 | 데이터 출처 | 소요 |
|---|---|---|---|
| A. 실제 검사 흐름 | 사진 접수 → 실제 AI 분석·Grad-CAM → 앱 모니터링 반영 → 상세 → 작업자 판정 → 이력. **분석 성공 시 REVIEW, 분석 실패 시 FAILED** | 실제 DGX e02 + 백엔드 실서버 | 5분 |
| B. 자동 통과 정책 | 카울커버 정상 사진이 1.63%에서 **AUTO_PASS** → 관리자가 1.00%로 조정·적용 → 같은 사진이 **REVIEW** → 원래 기준 복귀. 이전 기록은 판정 당시 기준치 그대로 | **실제 DGX 카울커버** + 백엔드 실서버 (재시작·DB 수정 없음) | 3분 |
| C. 오류 복구 (선택) | AI 실패 → FAILED → "AI 분석 없이 작업자 판정" 수동 전환 → 판정 (또는 재검사) | 실서버, 시연 중 새로 만든 FAILED 건 | 2분 |

- B의 정책 조정은 지금은 Swagger(ADMIN 로그인)로 실행하고, 결과는 앱 모니터링·이력·상세로 보여줌
  - **11/13 F11 통과** (INS-000122 AUTO_PASS → 앱에서 `-t1` 적용 → 123 REVIEW → 앱에서 복귀, 새 버전 없음): PR #20 병합 후 8·10·12번을 앱 화면으로 바꾸고 Swagger는 백업으로 둠. 앱은 1.00% 버전이 이미 있으면(`-t1`) 새로 저장하지 않고 그 버전을 적용함 → 10번이 "조정(새 버전 저장)"이 아니라 "이미 저장된 1.00% 버전 적용"이 됨. 시연에서 저장까지 보여줄지는 팀 결정
- 첫 접수는 다운로드가 느릴 수 있으니(11/11 16초) 시작 전 예비 접수를 해 둠. 시연 후 원래 정책(`cowl-e08-demo-0163`) 적용 상태 확인(`-t1`은 비활성으로 남겨도 됨)
- 실서버 장애 시 B는 앱 Mock 화면으로 대체 (11/12 도어 0.84→0.92%, PR #24 11/12 main 병합). 9장(도어 Mock 서버)은 재시작이 필요해 쓰지 않음
- 프레임은 정상 사진(약 1.2%)이 범위 최솟값 3.00%보다 낮아 기준치 조정 효과가 없음 → 필요하면 A 구간 뒤 "실제 AI 자동 통과·기준 초과·불량+LayerCAM" 3장 예시로만 사용

## 6. 장애 대비

| 상황 | 증상 | 대응 |
|---|---|---|
| 네트워크 느림 | 분석이 10초 넘게 걸림 | 타임아웃 20초라 대부분 완료됨. 넘으면 FAILED → C(재검사)로 이어서 설명 |
| AI 서버 응답 없음 | `/parts`의 modelAvailable=false, 접수 건 FAILED | 김도현 재실행. 안 되면 백업 영상으로 A 구간 대체 |
| Mac이 Tailscale에서 사라짐 | 앱 `NETWORK_ERROR` | Mac 잠자기 확인, Tailscale 재연결. 안 되면 같은 와이파이(backend README "앱 연결") 또는 백업 영상 |
| 계정 잠김 (비밀번호 5회 실패) | 423 `AUTH_ACCOUNT_LOCKED` | ADMIN으로 `POST /api/v1/admin/users/{loginId}/unlock` (Swagger) |
| 앱 화면 오류 | 화면이 안 뜸 | Swagger UI로 같은 API를 보여주며 설명 |
| 이미지가 안 보임 | 상세에서 이미지 오류 | 상세 다시 열기 (서명 주소 10분 만료) |

## 9. (사용 안 함) 도어 Mock 서버로 B를 보여줄 때

백엔드를 Mock AI로 바꿔 재시작해야 하므로 A 구간이 끝난 뒤에만 합니다.

1. Mock AI 실행: `cd backend/mock-ai && .venv/bin/uvicorn main:app --port 8090`
2. 모델 전환 (DB)
   ```sql
   UPDATE ai_model SET active = FALSE WHERE model_version = 'door-swin-tiny-e02-28a2dd1cb40b-dev';
   UPDATE ai_model SET active = TRUE  WHERE model_version = 'mock-door-swin-t-v1';
   ```
3. 백엔드 재시작: `APP_AI_BASEURL=http://localhost:8090`
4. ADMIN API: `example-door-p1` 중지 → `example-door-demo-0092` 적용 → Mock 시나리오 `GOOD_DEMO_0088` 접수(AUTO_PASS) → threshold 0.0084 → `-t1` 적용 → 다시 접수(REVIEW) → 원래 정책 재적용 (backend README "시연 정책", 11/12 AI 내부 평가 값)
5. 되돌리기: 시연 정책 중지, 위 SQL을 반대로 실행, `APP_AI_BASEURL`을 8771로 되돌리고 재시작
