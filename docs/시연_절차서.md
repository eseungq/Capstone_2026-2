# 시연 절차서 (초안)

작성: 이승규 · 11/10 초안 · 리허설 후 팀 확인을 거쳐 확정
기준: [API 계약 v4](백엔드_API계약_v4.md), [통합 점검표](통합_점검표.md), [backend/README](../backend/README.md) "시연 정책", [mobile/README](../mobile/README.md)

> 실제 AI(e02)는 보정기가 없어 **모든 결과가 작업자 확인(REVIEW)** 입니다. 자동 통과(AUTO_PASS)는 AI가 정한 시연 기준(30%)을 **Mock으로 재현한 구간에서만** 보여줍니다. 두 구간을 섞지 않고 화면·설명에서 구분합니다.

## 1. 시연 구성

| 구간 | 보여줄 것 | 데이터 출처 | 소요 |
|---|---|---|---|
| A. 실제 검사 흐름 | 사진 접수 → 실제 AI 분석·Grad-CAM → 앱 모니터링 반영 → 상세 → 작업자 판정 → 이력. **분석 성공 시 REVIEW, 분석 실패 시 FAILED** | 실제 DGX e02 + 백엔드 실서버 | 5분 |
| B. 자동 통과 정책 | 시연 기준 30%에서 REVIEW → 관리자가 35%로 조정·적용 → 같은 입력이 AUTO_PASS, 이전 기록은 30% 그대로 | 앱 Mock 시연 화면(PR #12) | 3분 |
| C. 오류 복구 (선택) | AI 실패 → FAILED → 재검사로 복구 (수동 판정이 구현되면 "AI 분석 없이 작업자 판정" 전환도) | 실서버 기존 FAILED 건 | 2분 |

- B는 백엔드 설정을 바꾸지 않고 **앱 Mock 화면**으로 보여줍니다. 서버로 같은 흐름을 보여줘야 하면 9장 "B를 실서버로 보여줄 때"를 따릅니다 (재시작이 필요해 리허설 필수).

| 사람 | 맡는 일 |
|---|---|

## 3. 사전 준비

### 하루 전
- [ ] 시연 장소 네트워크 확인: Mac **업로드 속도**(최소 10Mbps 이상, 가능하면 유선). AI가 Mac에서 사진을 받아가므로 업로드가 느리면 분석이 늦어짐 (11/09 실효 1.4Mbps에서 DEFECT 타임아웃)
- [ ] 리허설 1회 (5장 체크리스트) 후 **백업 영상** 녹화 (A·B 구간)
- [ ] 시연에 쓸 사진 준비: GOOD 1장, DEFECT 1장 (`조원 자료/9주차/DGX_AI_연결시험자료_20261104`, 공개 레포에 올리지 않음)
- [ ] 판정(confirm)·재검사(retry)에 쓸 검사 건을 미리 정해 둠 (실행하면 되돌릴 수 없음)

### 시작 1시간 전
- [ ] Mac 전원 연결, 잠자기 방지: 터미널에서 `caffeinate -dimsu` 실행해 두기
- [ ] Docker Desktop → `docker start inspection-mysql`
- [ ] IntelliJ 환경변수 확인 후 백엔드 실행
  `DB_PORT=3307;APP_AI_BASEURL=http://100.81.8.101:8771;PUBLIC_BASE_URL=http://100.117.82.89:8080;APP_PUSH_ENABLED=true;JWT_SECRET=<시연용 32자 이상 임의 값>`
  - `JWT_SECRET`은 공개 레포의 기본값 대신 시연용 값으로. 바꾸면 기존 로그인은 모두 다시 해야 함
- [ ] 김도현: 8771 실행·모델 목록 200 확인 (자동 복구 설정 유지)
- [ ] 연결 점검: `backend/scripts/check-ai-connection.sh http://100.81.8.101:8771 http://100.117.82.89:8080 <GOOD 사진>` → 모두 OK, inferenceTimeMs 3초 안팎
- [ ] DEFECT 1장 시험 접수 → COMPLETED·CAM 생성, 10초 안쪽이면 네트워크 정상
- [ ] 홍승인: iPhone Tailscale 연결, 앱 `.env.local`의 `EXPO_PUBLIC_API_URL` 확인, WORKER·ADMIN 로그인
- [ ] 김남균: 무결성 점검 SQL 0건 확인

## 6. 장애 대비

| 상황 | 증상 | 대응 |
|---|---|---|
| 네트워크 느림 | 분석이 10초 넘게 걸림 | 타임아웃 20초라 대부분 완료됨. 넘으면 FAILED → C(재검사)로 이어서 설명 |
| AI 서버 응답 없음 | `/parts`의 modelAvailable=false, 접수 건 FAILED | 김도현 재실행. 안 되면 백업 영상으로 A 구간 대체 |
| Mac이 Tailscale에서 사라짐 | 앱 `NETWORK_ERROR` | Mac 잠자기 확인, Tailscale 재연결. 안 되면 같은 와이파이(backend README "앱 연결") 또는 백업 영상 |
| 계정 잠김 (비밀번호 5회 실패) | 423 `AUTH_ACCOUNT_LOCKED` | ADMIN으로 `POST /api/v1/admin/users/{loginId}/unlock` (Swagger) |
| 앱 화면 오류 | 화면이 안 뜸 | Swagger UI로 같은 API를 보여주며 설명 |
| 이미지가 안 보임 | 상세에서 이미지 오류 | 상세 다시 열기 (서명 주소 10분 만료) |

## 8. 설명할 때 지킬 표현

- 실제 AI 결과는 "현재 검증된 자동 통과 기준이 없어 모두 작업자 확인"
- 30%는 "AI 담당이 고른 **시연 기준**, 같은 평가 사진에 사후 적용한 값으로 운영 기준 아님"
- 자동 통과 화면은 "Mock 재현"이라고 밝힘

## 9. B를 실서버로 보여줄 때 (선택, 리허설 필수)

백엔드를 Mock AI로 바꿔 재시작해야 하므로 A 구간이 끝난 뒤에만 합니다.

1. Mock AI 실행: `cd backend/mock-ai && .venv/bin/uvicorn main:app --port 8090`
2. 모델 전환 (DB)
   ```sql
   UPDATE ai_model SET active = FALSE WHERE model_version = 'door-swin-tiny-e02-28a2dd1cb40b-dev';
   UPDATE ai_model SET active = TRUE  WHERE model_version = 'mock-door-swin-t-v1';
   ```
3. 백엔드 재시작: `APP_AI_BASEURL=http://localhost:8090`
4. ADMIN API: `example-door-p1` 중지 → `example-door-demo-30` 적용 → Mock 시나리오 `GOOD_DEMO_ADJUST` 접수(REVIEW) → threshold 0.35 → `-t1` 적용 → 다시 접수(AUTO_PASS) (backend README "시연 정책")
5. 되돌리기: 시연 정책 중지, 위 SQL을 반대로 실행, `APP_AI_BASEURL`을 8771로 되돌리고 재시작
