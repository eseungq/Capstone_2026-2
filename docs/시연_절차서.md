## 1. 시연 구성과 핵심 원칙

| 구간 | 시연 내용 | 실제 데이터 출처 | 목표 시간 |
|---|---|---|---|
| A. 검사 흐름 | DEVICE 사진 접수 → AI 판정·판단 근거 이미지 → WORKER 모니터링·상세 → PASS/FAIL 최종 판정 → 이력 | 실제 DGX DOOR e02(8771) + 백엔드 + iPhone | 5분 |
| B. 정책 효과 | COWL_COVER 동일한 정상 사진: **1.63%에서 AUTO_PASS → 기존 1.00% 정책 적용 후 REVIEW → 원래 1.63% 정책 복귀** | 실제 DGX COWL_COVER(8778) + 백엔드 + iPhone ADMIN | 3분 |
| C. 장애 대응 (선택) | FAILED 상세 → 재검사 또는 새 MANUAL 검사로 전환해 작업자 판정 | 실제 기록과 이전 공동시험 결과, 필요시 팀 합의하에 새 시험 | 2분 |

- 도어 e02는 **보정기·활성 자동 통과 정책이 없어 GOOD이어도 REVIEW**입니다. DOOR의 실제 서버 결과와 앱 독립 **Mock 0.84→0.92% 시연**을 혼동하지 않습니다.
- COWL_COVER는 **사전에 준비돼 있던** `cowl-e08-demo-0163`(1.63%)과 `cowl-e08-demo-0163-t1`(1.00%)을 사용합니다. 시연 중 `POST /admin/policies/{id}/threshold`로 같은 1.00% 새 버전(`-t2`)을 중복 생성하지 않습니다. **정책 적용은 iPhone ADMIN 화면**에서 하며 Swagger는 장애 시 백업입니다.
- 5초는 모니터링 **기본 폴링 주기**이지 접수부터 화면 반영까지의 보장 시간이 아닙니다. AI 처리와 네트워크 지연이 추가됩니다. 분석 실패 시 FAILED도 정상적인 별도 분기입니다.
- iPhone의 신규 REVIEW/FAILED **앱 내부 배너는 포그라운드 폴링 기능**입니다. iOS 원격 푸시/앱 종료 중 알림으로 설명하지 않습니다.
- 이번 시연 기준은 **연구·개발용 평가 기준**입니다. 실제 산업 현장에 적용할 운영 안전성이나 독립 검증이 완료됐다는 뜻이 아닙니다. 검사 이력은 정책 변경 후에도 소급 재계산되지 않습니다.
- 모니터링과 상세의 `SERVER`·`Mock` 표시를 확인하고, **앱이 서버 원본 이미지·조회 데이터를 사용**하는 화면만 실서버 시연으로 설명합니다.
