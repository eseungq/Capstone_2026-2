## 4. 중단 및 복구

- **GET 조회 실패·예상 정책 불일치:** 어떤 POST도 실행하지 말 것. 서버 및 로그인 권한부터 확인.
- **적용 POST timeout / 409 / 연결 끊김:** **같은 POST를 반복하지 말고 GET으로 실제 활성 상태를 먼저 확인**. 적용 성공/실패 여부를 승규님과 공유.
- **1.00% 적용 이후 AI 장애 / 같은 사진 AUTO_PASS:** 정책 확인만으로 성공 주장하지 말고 검사별 AI 결과·정책 참조를 승규님·도현님과 확인. **원래 1.63% 정책 복귀를 먼저 완료**.
- **iPhone 정책 화면 오류:** 승규님이 ADMIN Swagger에서 GET으로 현재 상태 확인 후, 원래 `cowl-e08-demo-0163` 정책을 적용할지 판단하고 복귀 GET을 검증. **중복 POST 금지**.
- **이미 있는 -t1을 다시 저장하지 않기.** 새 버전 저장 201까지 별도로 검증할 필요가 있다면 시연 전 승규님과 **허용 기준치 및 생성 절차 합의**가 필요.
- **배너가 안 뜨는 경우:** 모니터링 최초 폴링 완료 후 새 검사를 접수했는지, 앱 활성 상태·서버 queue·5초 폴링 성공 여부를 먼저 확인. 서버 오류나 최초 조회 baseline 문제를 구분.
- **마지막 필수 확인:** 원래 **1.63% active** 여부를 서버 GET으로 검증. 실패 시 종료/Ready 전환하지 말고 백엔드 담당에게 복구를 인계.
