# mobile · 작업자·관리자 앱

담당: 홍승인

현재 기준: PR #68의 모바일 최종 통합 후보. main 병합 여부는 GitHub에서 확인합니다.

- 실제 계정 로그인, 부품별 모니터링·상세·원본/Grad-CAM 확대, 작업자 판정·재확인·일괄 FAIL, 관리자 판정 확인 요청 처리를 제공합니다.
- 관리자는 관리 탭에서 도어·프레임·카울커버의 자동 판정 정책과 날짜별 이력을 조회합니다. 정책 저장은 새 비활성 버전 생성이며 적용은 별도입니다.
- 로그인 화면의 Mock 시연 진입 버튼은 제거했습니다. 현재 로그인 화면에서는 실제 작업자/관리자 계정으로 로그인합니다.
- 알림은 앱 실행 중 폴링 기반 내부 배너이며, 백그라운드·종료 상태의 원격 푸시는 제공하지 않습니다. 기존 통계 화면은 Mock입니다.

## 실행과 서버 연결

1. `mobile/`에서 잠금 파일 기준으로 `npm ci`를 실행합니다.
2. 팀에서 제공한 API base URL을 로컬 `.env.local`의 `EXPO_PUBLIC_API_URL`에 설정합니다. 주소에는 `/api/v1`까지 포함합니다. 계정·토큰·환경설정 파일은 커밋하지 않습니다.
3. `npx expo start --go --lan --clear`를 실행하고, 같은 Wi-Fi의 iPhone에서 QR을 스캔합니다.
4. 실제 서버가 Tailscale에 있으면 iPhone의 Tailscale 연결을 유지합니다. PC는 Expo LAN만 제공할 수 있으므로 PC의 백엔드 접속 실패만으로 서버 장애를 판단하지 않습니다.

연동 기준: [API 계약 v4](../docs/백엔드_API계약_v4.md). iPhone의 `localhost`는 개발 PC가 아닙니다.

## 현재 iPhone 시연 절차

1. Expo Go로 앱을 열고 **실제 관리자 계정으로 로그인**합니다. Mock ADMIN 선택 단계는 없습니다.
2. 관리 → 자동 판정 정책에서 **도어 / 프레임 / 카울커버**를 선택하고, 해당 부품의 활성 정책·기준치·준비 상태를 확인합니다.
3. 정책 변경 시연은 팀이 승인한 시험 부품·정책·값으로만 진행합니다. 화면에 표시된 서버 검증 범위 안에서 새 비활성 버전을 저장하고, 확인창을 거쳐 별도로 적용합니다. 저장만 한 상태에서는 기존 적용 정책이 유지됩니다.
4. 백엔드 담당자가 제공한 신규 시험 검사로 모니터링 → 상세 → 원본/제공 Grad-CAM 확대 → 작업자 판정 → 이력을 확인합니다. 제출은 실제 작업자 계정과 승인된 시험 데이터로 진행합니다.
5. 정책 변경 시연을 했다면 기존 정책으로 복귀하고, 서버 목록의 활성 상태를 확인합니다. 기존 시험 검사에 중복 제출하지 않습니다.
6. 설정에서 로그아웃하고, 뒤로가기·앱 재실행으로 보호 화면에 재진입하지 않는지 확인합니다.

## 과거 독립 Mock 시나리오 참고

기존 도어 **0.84% → 0.92%** 비교는 보정 불량 확률 0.88%인 가상 사진을 사용한 독립 Mock 시나리오입니다. 현재 로그인 화면에서 이 시연으로 진입하지 않습니다. 남아 있는 개발용 코드·테스트의 비교값이며 실제 부품의 현재 서버 기준치, 품질 정확도 또는 독립 검증 근거로 사용하지 않습니다.
