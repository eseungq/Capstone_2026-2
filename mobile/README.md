# mobile · 작업자·관리자 앱

담당: 홍승인

React Native, Expo Router, TypeScript로 만든 모바일 앱입니다. 실서버 모드에서는 백엔드의 검사 기록과 활성 정책을 사용합니다.

## 실서버 연결과 실행

1. `mobile/.env.local`에서 `EXPO_PUBLIC_API_URL`을 iPhone이 접근할 수 있는 백엔드 주소로 설정합니다. 같은 네트워크의 개발 PC 주소나 Tailscale 주소를 사용합니다. iPhone에서 `localhost`는 iPhone 자체를 가리킵니다.
2. 저장소 루트에서 다음 명령을 실행하고 iPhone의 Expo Go로 프로젝트를 엽니다.

```sh
cd mobile
npm ci
npm start
```

서버 실행 방법과 API 명세는 [백엔드 README](../backend/README.md)와 [API 계약 v4](../docs/백엔드_API계약_v4.md)에 있습니다.

## `main`에서 사용하는 기능

| 화면 | 사용 방법 |
|---|---|
| 모니터링 | DOOR·FRAME·COWL_COVER를 전환해 대기 건수와 최근 검사의 썸네일을 봅니다. 모니터링 화면이 포그라운드에 있는 동안 기본 5초마다 조회하며, 새 REVIEW·FAILED 배너를 누르면 상세로 이동합니다. |
| 상세·판정 | 검사번호와 상태, 원본 사진, 제공된 AI 판단 근거를 확인합니다. 사진을 누르면 확대할 수 있습니다. WORKER는 REVIEW에 PASS/FAIL을 제출합니다. FAILED에서는 재검사를 요청하거나 WORKER가 수동 판정으로 전환할 수 있습니다. |
| 이력 | 상태·접수 기간·부품으로 필터링하고 이전·다음 페이지에서 기록을 찾아 상세를 엽니다. |
| 관리자 정책 | ADMIN은 COWL_COVER 활성 기준과 허용 범위를 조회하고 새 버전을 저장합니다. 저장한 버전을 적용하거나 기존 버전을 다시 활성화할 수 있습니다. |

모니터링 썸네일과 연결 상태(#33), 상세 사진 확대와 만료 주소 재조회(#37), 이력 필터와 버튼 터치 피드백(#38)은 `main`에 반영됐습니다. 이후 화면을 정리할 때도 역할별 판정 권한, 중복 제출·알림 방지, 정책 적용 전후 재조회를 확인합니다. iOS 원격 푸시 등록·수신은 미구현입니다. DOOR 정책과 통계의 Mock 시연은 설정에서 접근하는 별도 화면입니다.

## 도어 0.84% → 0.92% AUTO_PASS 독립 Mock 시연 (2026-11-12 도현님 변경 안내)

- 도현님 내부 평가 안내: **정책 기본값 0.92%**, 시연 조정 범위 **0.84~0.92%**. 비교 시나리오 시작 시 Mock **0.84% 정책을 활성화**하고, 다음 버전을 **0.92%**로 저장한 뒤 별도 적용합니다.
- 시연 전용 모델: `mock-door-swin-t-v1`, 시작 정책 `example-door-demo-0084` (0.0084), 새 정책 `example-door-demo-0084-t1` (0.0092).
- 비교 입력: AI 예측 `GOOD`, 보정 불량 확률 **0.88%** (코드 값 `0.0088`). 정책 `0.0084`에서 **REVIEW (ABOVE_THRESHOLD)**, 정책 `0.0092`에서 **AUTO_PASS / PASS / SYSTEM**으로 Mock 기록 표시.
- 이 시연은 앱 메모리에서 실행합니다. 실서버에서는 보정기가 없는 e02(8771)에서 REVIEW를 확인했고, 11/17에는 보정기가 있는 e02(8785)에서 시연 정책을 적용해 0.84% 기준 REVIEW와 0.92% 기준 AUTO_PASS를 확인했습니다. [F13 공동시험 기록](../docs/통합_점검표.md)
- 이 화면의 수치는 시연용 내부 평가 안내이며 독립적인 운영 안전성 검증/운영 정책 적용 근거로 간주하지 않습니다.

### iPhone 시연 절차

1. Expo Go에서 **Mock ADMIN** → 설정 → 자동 통과 기준 → 정책 조정 화면 → **DOOR 0.84% → 0.92% 정책 조정 · 독립 Mock 시연**.
2. 초기 활성 정책 **0.84%**에서 `GOOD / 0.88% 새 검사 접수 · Mock` → `REVIEW (ABOVE_THRESHOLD)` 확인.
3. `passThreshold`에 **`0.0092`** 입력 (0~1 범위 원시 값, 화면 표시 **0.92%**) → **새 정책 버전 저장 · Mock**. 저장만 하고 아직 적용하지 않은 상태에서 새 접수 시 `REVIEW` 유지.
4. **저장된 새 정책 적용 · Mock** → 같은 `GOOD / 0.88%` 새 검사 접수 → `AUTO_PASS · SYSTEM 최종 PASS`, 이전 REVIEW 시연 기록은 그대로.
5. 화면에 **서버 API 요청 없음**, **운영 정책/검사 기록 변경 없음** 안내가 표시되는지 확인합니다.
6. **시연 초기화**를 누르면 0.84% 시작 상태로 복귀합니다. 이 동작도 Mock 메모리 상태만 초기화합니다.
