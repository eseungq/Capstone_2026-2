## 4.3 데이터베이스 요구사항

### FR-DB-01 검사 기록과 처리 상태 저장

| 항목 | 내용 |
|---|---|
| 설명 | 사진 접수 시 검사 ID, 표시용 검사 번호(inspection_no), 부품·검사항목, 접수 계정과 경로(source), 접수·촬영 시각, 선택 라인 코드와 원본 이미지 참조를 한 트랜잭션으로 저장한다. 처리 상태는 RECEIVED → ANALYZING → COMPLETED 또는 FAILED로 갱신하며, 갱신할 때 직전 상태를 조건으로 걸어 중복·지연 반영을 막는다. FAILED는 오류 코드·상세·추적 ID를 저장하고 예측값은 저장하지 않으며, 이후 변경하지 않는다. |
| 입력값 | 접수 정보(이미지 메타데이터, partCode, lineCode, capturedAt, Idempotency-Key), 상태 변경 요청 |
| 출력값 | inspection, image_storage(ORIGINAL) 레코드 |
| 우선순위 | 높음 |
| 예외 상황 | DB 또는 저장소 실패, 같은 요청 재전송, 확정된 검사의 상태 변경 시도 |
| 검증 방법 | 저장 실패 시 검사나 이미지 한쪽만 남지 않는지, inspection_no 중복 거부, 같은 Idempotency-Key 재전송 시 새 검사가 생기지 않는지, FAILED 이후 상태 갱신이 0행인지 확인 |

### FR-DB-02 AI 결과·판정 근거와 Grad-CAM 이미지 저장

| 항목 | 내용 |
|---|---|
| 설명 | 분석 완료 시 AI 예측(predicted_quality, 보정 전 점수, 보정 확률, 보정기 버전, 모델), 정책 적용 결과(정책 준비 여부, 적용 정책, 판정 당시 기준치 스냅숏, recommended_action, review_reason)와 gradcam_status를 저장한다. AUTO_PASS는 GOOD 예측이고 준비된 정책이 있으며 보정 확률이 기준치 이하일 때만 저장할 수 있다. Grad-CAM은 원본에 겹친 판단 근거 이미지로 저장하며 결함 좌표·마스크·면적으로 저장하지 않는다. 계산은 됐지만 위치별 강조 반응이 없으면(0맵·상수맵) gradcam_status를 NO_ACTIVATION으로 저장하고 이미지는 저장하지 않는다. 이미지 위치는 저장소 상대 키로 저장하고 만료되는 접근 주소는 저장하지 않는다. defect_detection은 신규 기록을 중단하고 과거 기록만 보존한다. |
| 입력값 | 계약 검증을 통과한 AI 응답, 적용 정책 |
| 출력값 | inspection 갱신, image_storage(GRADCAM) 레코드 |
| 우선순위 | 높음 |
| 예외 상황 | AUTO_PASS 조건 미충족 저장 시도(DEFECT 예측, 정책 미준비, 보정 확률 없음, 기준치 초과), REVIEW 사유와 값 불일치, Grad-CAM 상태와 이미지 불일치, Grad-CAM 생성 실패, 강조 반응 없음 |
| 검증 방법 | 허용되지 않는 상태 조합이 제약으로 거부되는지, GENERATED와 GRADCAM 이미지 행이 일치하는지, 검사당 원본 1건·Grad-CAM 0~1건인지, Grad-CAM 생성 실패·강조 반응 없음일 때도 검사가 COMPLETED로 남는지 확인 |

### FR-DB-03 작업자 확인 결과 분리 저장

| 항목 | 내용 |
|---|---|
| 설명 | REVIEW 대기 검사의 최종 판정을 worker_confirmation(작업자, 확인 시각, 판정, 메모)에 저장하고, inspection의 final_judgement와 judged_by(WORKER)를 같은 트랜잭션에서 갱신한다. AI 예측과 정책 적용 결과는 변경하지 않는다. AUTO_PASS는 judged_by를 SYSTEM으로 저장하며 작업자 확인 기록을 만들지 않는다. |
| 입력값 | inspectionId, finalJudgement, workerId, comment |
| 출력값 | worker_confirmation 레코드, inspection 판정 갱신 |
| 우선순위 | 높음 |
| 예외 상황 | 확인 대상이 아님(AUTO_PASS, FAILED, 분석 중), 동시 제출, 같은 값 재전송, 다른 값 재제출 |
| 검증 방법 | 원본 AI 필드가 변경되지 않는지, 검사당 확인 기록이 1건인지, 최종 판정과 확인 기록 값이 일치하는지, 동시 제출 시 1건만 저장되는지 확인 |

### FR-DB-04 검사 이력과 모니터링 조회

| 항목 | 내용 |
|---|---|
| 설명 | 부품별 최근 검사, 확인 필요(REVIEW 대기)·오류(FAILED) 목록, 기간·부품·표시 상태 조건의 검사 이력을 접수 시각 기준으로 조회한다. 화면 배지용 건수 외의 통계 집계와 API는 이번 범위에서 제공하지 않는다. 향후 통계를 위해 review_reason, line_code, captured_at, pass_threshold_applied 등 근거 값은 지금부터 저장한다. |
| 입력값 | 부품, 기간, 표시 상태, 페이지 또는 커서 |
| 출력값 | 검사 목록, 확인 대기·실패 건수 |
| 우선순위 | 높음 |
| 예외 상황 | 조회 결과 없음, 이미 재검사한 FAILED 건 |
| 검증 방법 | 같은 조건에서 목록 건수와 배지 건수가 일치하는지, 완료 순서와 관계없이 접수 시각 순으로 정렬되는지, 재검사한 FAILED 건이 확인 필요 목록에서 빠지는지 확인 |

### FR-DB-05 검사 상세와 이미지 조회

| 항목 | 내용 |
|---|---|
| 설명 | inspectionId로 검사 정보, AI 결과, 정책 적용 결과, 판정(판정 주체·확인자·확인 시각)과 원본·Grad-CAM 이미지 참조(상대 키, 크기, EXIF 방향, gradcam_status)를 조회한다. 만료되는 접근 주소는 백엔드가 조회할 때 생성한다. |
| 입력값 | inspectionId |
| 출력값 | 검사 상세 데이터, 이미지 참조 |
| 우선순위 | 높음 |
| 예외 상황 | 대상 검사 없음, 이미지 유실, Grad-CAM 없음(NOT_REQUIRED·FAILED·NO_ACTIVATION) |
| 검증 방법 | 저장 직후 재조회한 값이 저장한 값과 일치하는지, 판정 주체와 Grad-CAM 상태가 저장 값대로 조회되는지 확인 |

### FR-DB-06 분석 실패 검사의 재검사 연결

| 항목 | 내용 |
|---|---|
| 설명 | FAILED 검사를 재검사하면 원래 기록은 변경하지 않고 새 검사 행(새 inspection_no, source = RETRY, retry_of_inspection_id)을 만들어 저장된 원본 이미지 참조를 연결한다. FAILED 1건당 재검사는 1건만 허용한다. 정책 변경에 따른 과거 결과 재계산은 이번 범위에서 제외한다. |
| 입력값 | 원래 검사의 inspectionId |
| 출력값 | 새 inspection, image_storage(ORIGINAL) 레코드 |
| 우선순위 | 중간 |
| 예외 상황 | FAILED가 아닌 검사, 이미 재검사한 검사 |
| 검증 방법 | 원래 FAILED 행이 변경되지 않는지, 같은 검사의 두 번째 재검사가 거부되는지, 새 검사의 원본이 같은 저장 위치를 가리키는지 확인 |

### FR-DB-07 모델 및 자동 통과 정책 버전 관리

| 항목 | 내용 |
|---|---|
| 설명 | 부품·검사항목별 모델 버전과 보정기 버전, 자동 통과 정책(pass_threshold, validated_min·validated_max, 보정기 버전, 평가 근거, ready, active)을 기록한다. ready는 AI 검증 자료를 등록할 때 결정하고, active는 ready 정책만 가능하며 모델당 최대 1개로 유지한다. 기준치를 조정하면 기존 행을 수정하지 않고 검증 범위 안에서 새 버전(based_on_policy_id)을 만든다. 시연용 모델·정책은 mock-·example- 접두어로 실제와 구분한다. |
| 입력값 | 모델·정책 등록 정보, 기준치 조정 요청 |
| 출력값 | ai_model, automation_policy 레코드 |
| 우선순위 | 높음 |
| 예외 상황 | 중복 버전, 미준비 정책 활성화, 검증 범위 밖 기준치, 모델·보정기 버전 불일치 |
| 검증 방법 | 버전 유일성과 active 정책 유일성, 검증 범위 밖 기준치와 미준비 정책 활성화 거부, 기준 조정 후 과거 검사의 정책·기준치 스냅숏이 바뀌지 않는지, 검사의 부품·검사항목과 정책의 모델·검사항목 불일치가 복합 외래키로 거부되는지 확인 |
